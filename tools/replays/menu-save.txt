# Save and load: save slot 5 (ffx_005, the Thunder Plains agency kami0100,
# map 0x107), loaded without the title menu. Equip (main menu entry 4):
# Tidus's weapon Sonic Steel -> Brotherhood, so the save differs from
# ffx_005. Then the save sphere beside Tidus (Up, Circle: Save / Play
# blitzball / Cancel), Save: the PC save list (a Flash screen, keys),
# "New Save Data", "Save the game?" Yes: written as the first free slot
# (ffx_004) of the harness's sandboxed Documents folder (Options::home,
# ~/ffx-work/harness/<slot>/home, a fresh copy at every launch: the user's
# saves are never written), Backspace leaves the list. Back to the title
# the way a game over goes (`call` AtelJumpGameOver 0x0086da10: map 0x17,
# which goes on to memochek and the opening, map 0x15d; Start skips to the
# title proper), Load (Enter), list entry 1 (the newest manual save: the
# one just written; entry 0 is the autosave), Yes, and the save's map
# opens again with Brotherhood equipped (the Equip screen).
#
# Lockstep, fast mode. The save/load machine's state
# (g_SaveMachineState 0x00ce72e8; docs/formats/save.md) is waited on
# before every key: 1 building the save list, 2 its input, 3 "Save the
# game?", 5 writing, 2 again, 0 closed; on the load side 0xb list, 0xc its
# input, 0xd Yes/No. The Flash screens take keys a little after they are
# drawn, so each key comes 30-60 frames after its state. The map words
# (g_SaveData +0) are waited on through the title, and each field's shots
# on ctrl work 0's count (0x01325d94; count 101, as in field-walk.txt).
# No shots of the save or load lists: their dates are the files' times
# (the sandbox copy's and the save's, by the wall clock).
#
# Ranges: g_SaveData (0x0112ca90, 0x68c0 bytes: map, party, gil,
# inventory, the sphere grid block) without the play time (+0xbc, u32
# seconds: Atel_PlayTimeUpdate_0086ca20 counts it from graphicGetTime, so
# its ticks fall at another point of the script in every run, original
# code included), the save file buffer (g_SaveFileBuffer 0x01597f70,
# 0x6900) without the header's play time (+0x10) and CRC (+0x1a), the
# block's play time (+0xfc) and the CRC after the block (+0x64f4), all of
# which differed between two original runs. The map words (+0, range 0)
# and the word at +0x28 (range 2) are ranges of their own: at the load
# frame +0x29 took an in-between value for one frame in some runs (one of
# nine original runs, most Rust runs; the field's load timing). The save
# machine's state, list cursor and file counts (0x00ce72e8, 0x18), the
# slot list's present flags (0x00ce7c78, 200 words, range 11) and its
# entry 1's slot (g_SortedSaveTable 0x00ce7318 + 12, range 12; the other
# words are dates and seconds), message window 0. Ranges 11 and 12 each
# showed an extra or other first state in one original run: before the
# save, entry 1 is whichever sandbox copy sorts first, and the copies'
# times tie or not by the second they were made. run-all.sh leaves
# ranges 2, 11 and 12 out of the comparison (--ignore 2,11,12), and in
# hook-hit mode (--hits: slower first calls) 0, 4 and 7 as well: there
# the loaded block (map words and the rest) and the packed save's header
# passed through an in-between state for a frame, in 2 of 2 runs (0 of 9
# normal Rust runs). The waits on the map words, the counts in range 10
# and the file buffer still check the maps, the list and the save. Screenshots (menu-save-<n>.bmp): 1 Brotherhood equipped, 2 the
# save sphere's choice, 3 the field after saving, 4 the title, 5 the field
# after loading, 6 the Equip screen after loading.
